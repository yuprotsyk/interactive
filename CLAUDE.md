# CLAUDE.md: технічний гайд проєкту

Цей файл читає кожна нова сесія розробки (зокрема з ШІ), щоб одразу мати повний контекст. Мова проєкту й спілкування з автором: **українська**. Код, ідентифікатори й коментарі до коду можна писати українською чи англійською, але текст інтерфейсу, пояснення й повідомлення автору лише українською.

## 1. Що це

Колекція навчальних інтерактивних сторінок для студентів: теорія ймовірностей і математична статистика. Студент змінює дані чи параметри й одразу бачить результат. Сайт публікується на GitHub Pages: <https://yuprotsyk.github.io/interactive/> (репозиторій `yuprotsyk/interactive`).

Автор завантажує файли **вручну через вебінтерфейс GitHub**, тому сайт має лишатися набором статичних файлів, які не потребують збірки.

## 2. Архітектура

**Стек:** чистий HTML, CSS і JavaScript (ES5-сумісний стиль, `var`, функції; без модулів, без бандлера, без npm-залежностей на сайті; `package.json` існує лише для тестів). Tailwind та фреймворки не використовуємо. Малювання графіків на `<canvas>` (2D), без бібліотек графіків.

**Структура файлів:**

| Файл | Роль |
|---|---|
| `index.html` | Головна: картки сторінок, згруповані за розділами («Теорія ймовірностей», «Статистика») |
| `<тема>.html` | Окрема сторінка. **Одна тема = один файл** зі своїми `<style>` і `<script>` |
| `common.css` | Спільні змінні кольорів, типографіка, кнопки, панелі, світла й темна тема |
| `common.js` | Глобальний об'єкт `Stat`: форматування чисел, осі, кореляція, p-значення, розбір даних |
| `distributions.js` | Глобальний `Dist`: pmf/pdf/cdf, середнє, дисперсія, квантилі |
| `probability.js` | Глобальний `Prob`: повна ймовірність, формула Байєса, природні частоти |
| `summary.js` | Глобальний `Summ`: числові характеристики для окремих значень і інтервального ряду |
| `random.js` | Глобальний `Rand`: генератор із зерном і розподіли для симуляцій |
| `formulas.js` | Глобальний `Tex`: відображення формул через KaTeX (CDN) із запасним простим записом |
| `tests/*.mjs` | Тести Node (вбудований `node:test`) |
| `tests/fixtures/*.json` | Еталонні значення з Python (scipy/numpy) |
| `tests/browser/` | Браузерні перевірки (Playwright): `browser.test.mjs` запускає файли з `cases/`, по одному на сторінку, плюс `all-pages.mjs` для загальних перевірок |
| `package.json` | Лише для тестів: скрипти й `devDependencies` (Playwright). Сайт від нього не залежить |
| `.github/workflows/test.yml` | Автоматичний запуск усіх тестів на GitHub при кожному завантаженні файлів |
| `tools/*.py` | Скрипти, що генерують еталони |

**Підключення скриптів:** класичні `<script src="...">` у порядку залежностей (`common.js` першим). Кожен спільний файл завершується умовним `module.exports`, щоб його можна було `require` у тестах Node. Спільні файли **не залежать від DOM**.

**Що де лежить:**
- Математика (формули, розрахунки) живе у спільних `*.js` і покривається тестами.
- Сторінка відповідає за інтерфейс: стан, події, малювання, тексти. Формули не дублюємо в HTML.
- Якщо логіка потрібна двом сторінкам, виносимо її у спільний файл і додаємо тест.

### Автономність сторінок

Кожна сторінка самодостатня щодо розмітки, стилів і поведінки. Це дозволяє завантажувати й оновлювати одну сторінку, не чіпаючи інші. Тому:
- Стилі сторінки лежать у її `<style>`, спільні підключаємо з `common.css`.
- Не робимо складних залежностей між сторінками. Єдине, що їх пов'язує: `common.*`, спільні математичні файли й посилання з `index.html`.
- Змінюючи спільний файл, перевіряйте **усі** сторінки, що його використовують (див. розділ 7).

### Довідник спільних модулів

Скористайтеся ним, перш ніж писати нову математику: найімовірніше, потрібна функція вже є. Повні коментарі лежать у самих файлах.

- **`Stat`** (`common.js`): `fmt(v, digits)`, `fmtSigned`, `fmtSig` (4 значущі цифри), `decimalsFor`, `snapToSpan`, `clamp`; осі: `niceStep`, `ticksFor(lo, hi, target)` → `{step, decimals, major, minor}`; `mean`, `pearson`, `spearman`, `ranks`, `pValue`, `fisherCI`, `analyze(points)`; спеціальні функції `lgamma`, `betai`; розбір вводу `toNumber`, `splitLine`, `parseData`.
- **`Dist`** (`distributions.js`): розподіли `binomial`, `geometric`, `poisson`, `hypergeometric` (дискретні: `pmf`, `cdf`, `support`) і `normal`, `exponential`, `uniform`, `chisq`, `student`, `fisher` (неперервні: `pdf`, `cdf`, `domain`); у всіх `mean(P)`, `variance(P)` (`null` означає «не існує», `Infinity` «розбіжне»); `gammaP`, `gammaQ`, `quantile`, `quantileDiscrete`; довірчий інтервал для математичного сподівання `critical(kind, level, df)` і `meanCI(values, level, method, opts)` (методи `"z"`, `"t"`, `"zs"`).
- **`Prob`** (`probability.js`): `setWeight`, `resize` (ваги гіпотез із сумою 1), `total`, `terms`, `posterior`, `sequence`, `apportion`, `counts`; для двох подій `jointRange`, `clampJoint`, `table2x2`, `cond`, `independence`; для трьох `independence3`.
- **`Summ`** (`summary.js`): за окремими значеннями `sorted`, `mean`, `median`, `quartiles`, `variance(v, ddof)`, `sd`, `series`, `modeRaw`, `box`; для інтервального ряду `group(v, start, h)` (за вимірами), `table(start, h, freqs)` (за готовими частотами), `gMean`, `gVariance`, `gQuantile(g, p)`, `gMode`. Структура ряду: `{start, h, n, m, iv: [{a, b, mid, f, cum}]}`.
- **`Tex`** (`formulas.js`): `set(el, запис, [latex])` записує формулу в елемент; `text(el, рядок)` вставляє текст і сам знаходить у ньому формули; `mix(el, [рядок, {m: запис}, …])` змішаний підпис; `render(корінь)` домальовує `.tex`; `toTex(запис)` перетворює простий запис на LaTeX (без DOM, тестується).
- **`Rand`** (`random.js`): `create(seed)` повертає генератор з методами `next`, `int`, `uniform`, `bernoulli`, `normal`, `exp`, `cauchy`, `arcsine`, `bimodal`; `seedFor(seed, i)` дає окреме зерно для i-го запуску.

### Відомі пастки

- **Нова функція у спільному файлі й кеш.** Якщо сторінка використовує функцію, яку щойно додали в `random.js`, `summary.js` чи інший спільний файл, а автор завантажив лише сторінку, на сайті спрацює стара версія файлу й кнопки «мовчки» перестануть працювати. Тому при кожній зміні спільного файлу перелічуйте його у списку для завантаження й нагадуйте про Ctrl+F5.
- **Полотно ще не має розмірів.** Якщо сторінку рахують до першого `ResizeObserver`, ширина `canvas` дорівнює нулю: захищайтеся від від'ємних радіусів і ділення на нуль під час малювання.
- **Крайні значення інтервалу.** Максимум на верхній межі останнього інтервалу не створює додаткового інтервалу: див. `Summ.group`. Не повертайтеся до `floor((max − x₀)/h) + 1`.
- **Знімки екрана в Playwright.** Після зміни стану зачекайте приблизно 1 секунду перед `fullPage`, інакше знімок може зависнути через таймер `aria-live`.

## 3. Домовленості щодо термінології та математики

Терміни (узгоджені з автором, не змінювати без запитання):
- **Вибіркове середнє** x̄ (середнє за даними) і **математичне сподівання** μ, E(X) (теоретичне значення) чітко розрізняємо. На сторінках статистики пишемо «вибіркове середнє», а не просто «середнє». Довірчий інтервал будуємо для математичного сподівання.
- «щільність», «показниковий» розподіл, «хі-квадрат», «квартилі».
- Накопичені частоти. Дискретна ознака: **емпірична функція розподілу F\*(x)** (східчастий графік, кумулята). Неперервна ознака (інтервальний ряд): **кумулята (кумулятивна крива)**, ламана за верхніми межами інтервалів.
- Викиди за правилом 1,5·IQR: «потенційні викиди».
- Точність: розрахунок **за початковими даними** дає **точні** значення, **за згрупованими даними** (інтервальний ряд) **наближені**, бо значення інтервалу замінено його серединою. На сторінках пишемо «за початковими даними (точно)» і «за згрупованими даними (наближено)».

Домовленості щодо обчислень:
- Інтервали групування `[a; b)`, останній замкнений `[a; b]`, щоб містити максимум.
- Квартили: медіани половин ряду (при непарному n медіану в половини не включаємо). Метод названо на сторінках.
- Дисперсія: перемикач «ділити на n / n − 1», за замовчуванням n.
- Коефіцієнт варіації лише для невід'ємних значень із додатним вибірковим середнім.
- Ймовірності гіпотез завжди в сумі 1; змінюючи одну, решту масштабуємо. Кольори гіпотез: `--h1…--h4`.
- P(A ∩ B) завжди в межах Фреше `[max(0, P(A) + P(B) − 1), min(P(A), P(B))]`. Несумісні події з додатними ймовірностями залежні. Розрізняємо «попарно незалежні» і «незалежні в сукупності».

### Академічна точність

Формули, розподіли й алгоритми беремо лише з класичних підручників, без власних спрощень чи інтерпретацій. Нову формулу супроводжуйте еталонним тестом (scipy/numpy). Якщо джерела немає або сумніваєтеся, запитайте автора, а не вигадуйте.

**Перед написанням будь-якої нової математики перегляньте «Довідник спільних модулів» (розділ 2)**, щоб не дублювати наявні функції.

### Формули на сторінках

Формули малюємо через **KaTeX з CDN** (jsDelivr, версія закріплена в `formulas.js`, із контрольними сумами SRI). Це єдина дозволена стороння бібліотека, крім шрифтів Google.

Як це працює: сторінка підключає `formulas.js` після `common.js` і пише формулу простим текстом (`P(A | B)·P(B)`, `x̄`, `σ²/√n`, `Σ xᵢ·fᵢ / n`). `Tex.toTex` перетворює такий запис на LaTeX, а KaTeX його малює. Якщо CDN недоступний, у тексті лишається простий запис, тож сторінка працює й без мережі.

Правила:
- **Статичний текст:** формулу обгортаємо в `<span class="tex">…</span>`.
- **Текст, який будує скрипт:** формульні рядки (таблиці, розрахунки, підписи, примітки) вставляємо через `Tex.set`, `Tex.text` або `Tex.mix`, а не через `textContent`. Це безпечно: дані користувача потрапляють у KaTeX лише як текст.
- **Складні формули** (дроби, степені, біноміальні коефіцієнти, корені з вкладенням) записуємо явним LaTeX: `Tex.set(el, простий_запис, latex)` або атрибут `data-tex`. Автоперетворення призначене для простих виразів.
- **Не в KaTeX:** текст усередині `<canvas>`, `aria-label`, `title`, `<option>`, `<title>` і рядок наведення на графік (його оновлюють часто). Там лишається простий запис із Unicode.
- Одиничні змінні в звичайному реченні («подія A», «n випробувань») окремо не обгортаємо. Обгортаємо вирази зі спеціальними символами й функціями: `P(…)`, `E(X)`, `x̄`, `σ`, `μ`, `Σ`, `√`, степені, індекси, `∩`, `∪`.
- Нову формулу беремо лише з підручника (див. «Академічна точність») і додаємо її зразок до тесту `tests/formulas.mjs`.
- Тести підміняють CDN локальним пакетом `katex` тієї самої версії (див. `tests/browser/browser.test.mjs`). Змінюючи версію KaTeX, оновіть `VERSION` і обидві контрольні суми в `formulas.js` та `devDependencies` у `package.json`.

## 4. Правила написання коду

- **Без збірки.** Код має працювати, якщо відкрити файл із диска (`file://`) або з GitHub Pages.
- **Без секретів і ключів.** У репозиторії публічний код, тому ніяких токенів, приватних адрес, особистих даних.
- **Без серверної частини й cookie.** Жодних запитів до власного бекенда. Зовнішні ресурси лише шрифти Google Fonts (із запасними системними шрифтами) і KaTeX для формул (розділ 3). Не додавайте аналітику, трекери й інші CDN-бібліотеки.
- **Стиль JS:** `"use strict"`, самовикликна функція для коду сторінки, `var`, функції-декларації, коментарі українською пояснюють «чому», а не «що». Глобальні об'єкти лише `Stat`, `Dist`, `Prob`, `Summ`, `Rand`, `Tex`.
- **Числа.** Форматуємо тільки через `Stat.fmt`, `Stat.fmtSig`, `Stat.fmtSigned`: десяткова кома, справжній мінус «−». Не виводимо `NaN`, `Infinity`, `undefined`: недоступне значення показуємо як «—» чи поясненням.
- **Точність.** Порівняння значень на межах інтервалів з допуском (`EPS`), без прямого `===` для дробових.
- **Випадкові числа:** лише `Rand` із зерном, щоб симуляцію можна було відтворити.
- **Динамічний текст** вставляємо через `textContent`, а не `innerHTML`, якщо там можуть бути дані користувача. Формули: через `Tex.*` (див. розділ 3).
- **Обмеження вводу:** перевіряємо межі (кількість точок, інтервалів, довжина вводу) і показуємо зрозуміле повідомлення замість мовчазного ігнорування.

## 5. UI/UX та адаптивність

**Mobile-first.** Розкладка спочатку для телефона (один стовпчик, ширина 360–390 px), потім ширші екрани.
- Типовий шаблон: CSS grid з іменованими областями. На мобільному `.main` і `.side` мають `display: contents`, від 900 px це два стовпчики (графіки зліва, показники справа).
- **Горизонтального прокручування сторінки не має бути** ні на 360, ні на 390 px. Широкі таблиці лежать у контейнері з `overflow: auto`.
- Мінімальна цільова область для дотику близько 40 px. Для полотен, що редагуються пальцем, `touch-action: none`.

**Тема.** Світла й темна тема через CSS-змінні в `common.css` (`prefers-color-scheme` і `data-theme`). Усі кольори беремо зі змінних, у полотні читаємо через `getComputedStyle`, а при зміні теми перемальовуємо.

**Графіки на `<canvas>`:**
- масштаб під `devicePixelRatio`, перемальовування через `ResizeObserver`;
- підписи з обводкою-«гало» кольору панелі, щоб не зливалися з лініями;
- не перевантажуємо графік: допоміжні лінії (середнє, медіана, мода, ±SD) вмикаються прапорцями.

**Доступність:**
- кожне поле й кнопка мають підпис (`label`, `aria-label`, `aria-labelledby`);
- перемикачі це `button` з `aria-pressed`;
- підсумок змін оголошуємо через `aria-live` (`#sr`, затримка-«debounce»), а `canvas` має змістовний `aria-label` з поточними числами;
- інтерактивні елементи доступні з клавіатури; клас `.sr-only` для прихованого тексту.

**Структура сторінки статистики** (еталон: `discrete-summaries.html`, `continuous-summaries.html`):
1. вхідні дані й налаштування (готові набори-«чипи», введення власних, скасування);
2. статистичний ряд (таблиця);
3. графіки;
4. числові характеристики з попередженнями;
5. «Детальні обчислення» у `<details>`, згорнуті за замовчуванням;
6. коротке пояснення «Що тут відбувається».

**Тексти:** короткі, математично точні, без дублювання формул і результатів у різних блоках. Чітко розрізняємо: варіаційний і інтервальний ряди; абсолютні, відносні, накопичені частоти; точні й наближені характеристики.

## 6. Додавання нової сторінки

1. Створіть `<тема>.html` за зразком найближчої сторінки (лише розмітка й стиль, математику в спільний файл).
2. Додайте математику у спільний `*.js` (або новий файл з умовним `module.exports`) і **тести** в `tests/`.
3. Додайте картку на `index.html` у потрібний розділ (заголовок, `eyebrow`, одне речення опису).
4. **Обов'язково** оновіть і `README.md` (список сторінок і таблиця структури), і `ROADMAP.md`.
5. Пройдіть перевірки з розділу 7.

## 7. Перевірка перед здачею

Усе автоматизовано, запуск з кореня проєкту:

```bash
node --test tests/*.mjs        # математика (Node 18+, без встановлення)
npm install && npx playwright install chromium   # один раз, для браузерних тестів
npm run test:browser           # браузерні перевірки всіх сторінок
```

(`npm run test:all` запускає обидва набори.) На GitHub те саме виконує `.github/workflows/test.yml`: червона позначка біля коміту означає, що щось зламалося.

**Що перевіряють браузерні тести** (файли в `tests/browser/cases/`):
- `all-pages.mjs`: кожна сторінка відкривається без помилок у консолі, усі формули KaTeX намальовано без помилок, немає горизонтального прокручування на 360, 390 і 1280 px, працює темна тема, у видимому тексті немає `NaN`/`Infinity`/`undefined`, `lang="uk"`, один `h1`, головна сторінка веде на всі сторінки (і лише на існуючі);
- `<сторінка>.mjs`: ключові числа на відомому прикладі й поведінка елементів керування;
- `<сторінка>-edge.mjs` і `summaries-edge.mjs`: крайні значення параметрів, порожні дані, n = 1, n = 2, усі значення однакові, інваріанти таблиць частот (сума частот = n, сума відносних = 1, остання накопичена = n, остання накопичена відносна = 1).

**Додаючи нову сторінку, додайте для неї файл у `tests/browser/cases/`** за зразком найближчої: `export default async function (h) { ... }`, де `h.browser` це браузер Playwright, а `h.pages` перелік сторінок. Картку на `index.html` перевіряє `all-pages.mjs`, тож перелік карток оновлювати в тестах не треба.

Дрібні правила:
- Знімок екрана (`fullPage`) робіть після невеликої паузи (≈1 с), бо на сторінках є таймер оголошень `aria-live`.
- Запити до Google Fonts тести блокують самі, тому мережа для них не потрібна.
- Якщо Playwright встановлено не локально, а глобально, запускайте з `NODE_PATH` на його `node_modules`.

Еталонні дані для тестів генерують скрипти в `tools/` (потрібні Python, numpy, scipy), результат пишеться в `tests/fixtures/`. Змінюючи алгоритм у `summary.js`, оновіть і Python-«оракул» у `tools/gen_summary_fixtures.py`, потім перегенеруйте еталони.
